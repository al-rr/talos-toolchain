# Day-1 Project Variables (`cluster.sh`)

This document describes the project variables consumed by
[`scripts/talos/cluster.sh`](/home/vagrant/talos-toolchain/scripts/talos/cluster.sh).

## Scope

Each generated cluster project is the source of truth for day-1 operations.

Typical layout:

- `vars.sh`: committed project baseline
- `vars.local.sh`: local or sensitive overrides, not committed
- `patches/`: machine config patches rendered/applied during day-1
- `generated/`: generated Talos artifacts

`cluster.sh` loads `vars.sh` first and then `vars.local.sh` if it exists.

## Contract

The current `cluster.sh` does not use `TALOS_DAY1_*` command mappings.
Those variables were removed.

The contract is now:

- project-driven
- action-based
- based on the variables generated by `create-project`

That means `cluster.sh` owns the day-1 flow directly:

1. `generate`
2. `provision`
3. `prepare-bootstrap`
4. `apply-config`
5. `bootstrap`
6. `apply-post-bootstrap`
7. `sync-access`

## Core Variables

Generated defaults include these groups.

### Cluster identity

- `TALOS_CLUSTER_NAME`
- `TALOS_CLUSTER_ENDPOINT`

### vSphere target (compatibility/reference)

The variables below describe the vSphere-backed provisioning interface
consumed by `provision-talos-vsphere`. They are documented here for
compatibility and reference only — a local macOS Talos cluster does not
require vSphere and does not need these variables set.

- `VSPHERE_ENDPOINT`
- `VSPHERE_USERNAME`
- `VSPHERE_PASSWORD`
- `VSPHERE_INSECURE_CONNECTION`
- `VSPHERE_DATASTORE`
- `VSPHERE_NETWORK`
- `VSPHERE_FOLDER`
- `VSPHERE_RESOURCE_POOL`

### Access identity

- `BUILD_USERNAME`
- `SSH_USER`
- `SSH_PORT`
- `HAPROXY_SSH_USER`
- `ANSIBLE_USER`
- `ANSIBLE_USERNAME`

### Load balancer topology

- `HAPROXY_VIP`
- `HAPROXY_NODE_1_NAME`
- `HAPROXY_NODE_1_IP`
- `HAPROXY_NODE_2_NAME`
- `HAPROXY_NODE_2_IP`

## Day-1 Post-Bootstrap Variables

These control the day-1 baseline addon phase executed by
`apply-post-bootstrap`.

- `TALOS_CLUSTER_BASELINE_ADDONS`
- `TALOS_BASELINE_ADDONS`
- `TALOS_DISABLE_DEFAULT_CNI`
- `TALOS_POST_BOOTSTRAP_HELM_AUTO_PREPARE`
- `TALOS_POST_BOOTSTRAP_HELM_SOURCE_MODE`
- `TALOS_POST_BOOTSTRAP_HELM_SOURCE_PATH`
- `TALOS_POST_BOOTSTRAP_HELM_SOURCE_URL`
- `TALOS_POST_BOOTSTRAP_HELM_OVERWRITE`

Current expected behavior:

- day-1 baseline is cluster-oriented
- `cilium` is typically part of day-1
- manifest source can come from a local path or a downloaded archive

## External Integration Hooks

These hooks exist so the toolchain stays reusable and does not embed lab-only
infrastructure modules.

### Load balancer hook

- `TALOS_LOAD_BALANCER_RECONCILE_SCRIPT`

If set, `prepare-bootstrap` can reconcile the Talos API frontend/backend
through an external script.

If empty, load balancer reconciliation is skipped.

### DNS hooks

- `TALOS_DNS_SYNC_REQUIRED`
- `TALOS_DNS_REGISTER_SCRIPT`
- `TALOS_DNS_UNREGISTER_SCRIPT`

These are optional integration points for environments that want Talos node DNS
records managed during provision/destroy.

Default behavior in the reusable toolchain should remain:

- `TALOS_DNS_SYNC_REQUIRED="false"`

## Practical Override Example

Example `vars.local.sh`:

```bash
export VSPHERE_PASSWORD="CHANGE_ME"
export TALOS_NAMESERVERS='["192.168.0.53"]'
export TALOS_LOAD_BALANCER_RECONCILE_SCRIPT="/path/to/lab/load-balancer-hook.sh"
export TALOS_DNS_SYNC_REQUIRED="true"
export TALOS_DNS_REGISTER_SCRIPT="/path/to/lab/register-hosts.sh"
export TALOS_DNS_UNREGISTER_SCRIPT="/path/to/lab/unregister-hosts.sh"
```

## Execution Order Reference

1. `cluster.sh create-project --project-dir=...`
2. Fill `vars.sh`
3. Optionally create and fill `vars.local.sh`
4. `cluster.sh refresh-schematics --project-dir=... --talos-version=vX.Y.Z`
5. `cluster.sh generate --project-dir=...`
6. `cluster.sh provision --project-dir=...`
7. `cluster.sh prepare-bootstrap --project-dir=...`
8. `cluster.sh apply-config --project-dir=...`
9. `cluster.sh bootstrap --project-dir=...`
10. `cluster.sh apply-post-bootstrap --project-dir=...`
11. `cluster.sh sync-access --project-dir=...`
